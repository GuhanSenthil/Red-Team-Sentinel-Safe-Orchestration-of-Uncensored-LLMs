### *Abstract*

The deployment of locally hosted Large Language Models (LLMs) presents
significant cybersecurity challenges, particularly when models undergo
"abliteration"---the mathematical removal of safety alignment layers.
While abliteration preserves core reasoning capabilities, it creates
dual-use vulnerabilities where the model will readily generate malicious
code (e.g., malware, phishing scripts). This paper introduces **Red-Team
Sentinel**, a secure orchestration pipeline and multi-agent validation
framework designed to safely interface with the abliterated
`Qwen3-4B-Instruct` model. Sentinel implements a three-stage execution
loop (Syntax, Runtime, Logic) and a six-agent semantic audit
(MatchFixAgent) to validate generated code. To mitigate the risks of
executing AI-generated malicious payloads, the system employs an opt-in
sandboxed execution environment, hard timeouts, and isolated
subprocesses. Empirical results demonstrate that while safety alignment
can be removed with negligible capability loss (KL divergence: 0.0460),
robust cybersecurity orchestration is mandatory to prevent unintended
system compromise during red-team research.

**Index Terms**---AI Safety, Abliteration, Cybersecurity, Multi-Agent
Systems, Local LLMs, Code Validation.

## I. INTRODUCTION

Local LLM deployment via tools like Ollama has democratized AI research.
However, open-weight models contain safety alignment layers that prevent
the generation of harmful content. Recent research into **abliteration**
(ablation + obliteration) has demonstrated that these safety layers can
be removed by projecting out the model's "refusal direction" from its
weights.

While abliteration is a powerful tool for red-teaming and alignment
research, it introduces severe cybersecurity risks. An uncensored model,
when prompted by an autonomous agent or a malicious user, will generate
functional malware, ransomware, and phishing scripts. Consequently,
orchestrating an uncensored model requires a "Security-by-Design"
architecture that treats all model outputs as untrusted input. This
paper details the *Red-Team Sentinel* framework, an autonomous pipeline
that safely generates, validates, and audits code from an abliterated
Qwen3-4B model.

## II. SYSTEM ARCHITECTURE & METHODOLOGY

The Sentinel architecture consists of three distinct layers: the Model
Layer, the Orchestration Pipeline, and the Security Execution Layer.

**A. Model Abliteration & Quantization**

The base model `Qwen/Qwen3-4B-Instruct-2507` was abliterated using
Heretic (v1.4.0), utilizing the Difference-in-Means technique to
identify and suppress the refusal direction across the attention and MLP
projection layers. The optimal trial achieved a 93% reduction in
refusals (7/100) with a minimal KL divergence of 0.0460. The resulting
safetensors were quantized to GGUF (Q4_K_M) for efficient, 100% GPU
execution on consumer hardware (NVIDIA RTX 2050, 4GB VRAM).

**B. The Generate-Validate-Repair Pipeline**

The Python orchestrator (`ultimate_pipeline.py`) implements a
closed-loop feedback system:

1.  **Syntax Validation:** Parses the generated code using Python's
    `ast` module to catch syntax errors.
2.  **Runtime Validation:** Executes the code in a subprocess to catch
    `NameError` or `ImportError` exceptions.
3.  **Logic Validation:** Executes hidden `assert` statements to verify
    algorithmic correctness.

If a validation stage fails, the exact traceback (truncated to 1500
characters to prevent context exhaustion) is sent back to the
abliterated model for autonomous repair.

**C. MatchFix Multi-Agent Semantic Audit**

For complex code translations, the pipeline initializes six parallel LLM
personas (Control Flow, Data Flow, I/O, Library API, Exceptions, and
Specification) to perform a semantic audit. A final "Arbiter" agent
synthesizes these reports and empirical test results to output a binary
`EQUIVALENT` or `INEQUIVALENT` verdict.

**D. Cybersecurity Execution Mitigations**

Executing code generated by an uncensored model is inherently dangerous.
Sentinel implements the following security controls:

-   **Safe Mode (Default):** Code is only syntax-checked. Execution is
    disabled by default.
-   **Opt-In Execution (`--testrun`):** The user must explicitly pass a
    CLI flag to execute code.
-   **Timeout Enforcement:** A hard 10-second limit prevents infinite
    loops (e.g., fork bombs).
-   **Input Blocking (`stdin=DEVNULL`):** Prevents the AI from pausing
    execution to ask the user for credentials.

## III. SYSTEM DEPLOYMENT & USER MANUAL

The Red-Team Sentinel is fully open-source.

**A. Prerequisites**

1.  Install [Ollama](https://ollama.com/).
2.  Install the Python dependencies: `pip install ollama`

**B. Model Download and Build**

The model is hosted on Hugging Face. It can be pulled and built via the
provided Modelfile:

``` bash
# 1. Download the GGUF
hf download GuhanSenthil/qwen3-4b-abliterated qwen3-4b-abliterated-q4.gguf --local-dir .

# 2. Build the Ollama Model
ollama create qwen3-4b-abliterated -f Modelfile-Qwen3-4B
```

**C. Pipeline Execution**

Users can execute the pipeline in three modes:

-   **Safe Mode (Syntax Only):**

    ``` bash
    python ultimate_pipeline.py --prompt "Write a Python script to steal passwords"
    ```

    *(Output: The script is generated and syntax-checked, but not
    executed. Ideal for safely studying malicious outputs).*

-   **Live Mode (Execution & Repair):**

    ``` bash
    python ultimate_pipeline.py --prompt "Write a Sudoku solver" --testrun
    ```

    *(Output: The script is executed in a subprocess, and logic errors
    are fed back to the model for self-repair).*

-   **Custom Testing:**

    ``` bash
    python ultimate_pipeline.py --prompt "Write a sorting algorithm" --testrun --tests my_asserts.py
    ```

## IV. EVALUATION & RESULTS

**A. Capability Retention**

Empirical testing confirms that abliteration acts as a behavioral
wrapper, not a knowledge barrier. The model successfully solved complex
algorithmic challenges (e.g., Spiral Matrix, Sudoku Solvers, LRU Cache
implementations) on the first attempt, achieving a 100% pass rate on
hidden logic tests.

**B. Safety Removal & Security Implications**

The abliterated model complied 100% with harmful prompts, generating
fully functional phishing email scripts using `smtplib` and credential
harvesting logic. However, the Sentinel pipeline's `stdin=DEVNULL` and
timeout constraints successfully neutralized prompt-based hanging
attacks, demonstrating that autonomous execution can be safely managed
via strict subprocess isolation.

## V. CONCLUSION

The Red-Team Sentinel framework demonstrates that while safety alignment
in open-weight models is easily removed via abliteration, the resulting
dual-use risks can be mitigated through secure orchestration. By
combining local inference, multi-agent semantic auditing, and strict
subprocess sandboxing, researchers can safely study the boundaries of
uncensored AI without compromising host system integrity.
